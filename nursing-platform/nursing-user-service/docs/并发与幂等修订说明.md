# 并发与幂等修订说明

更新时间：2026-07-10

## 个人资料乐观锁

- `user` 表新增 `version` 字段，作为个人资料编辑的乐观锁版本号。
- `GET /api/v1/users/profile` 返回 `version`。
- `PATCH /api/v1/users/profile` 请求体必须携带 `version`。
- 服务端执行 `WHERE id = ? AND version = ? AND is_deleted = 0` 的条件更新，成功后 `version = version + 1`。
- 若版本已过期但提交内容与当前资料完全一致，视为同一次请求的重复提交，直接返回成功。
- 若版本已过期且内容不同，返回 `409 / 2016`。
- 身份证比较使用解密后的明文；入库仍使用 `IdCardCrypto` 加密，响应仍脱敏。

## 文件上传幂等与去重

- `POST /api/v1/files/upload` 从 `UserTokenInterceptor` 写入的 `request.userId` 获取可信用户身份。
- 请求头 `Idempotent-Key` 必填，最长 64 个字符。前端为每个本地上传槽位生成一次，快速多点和重试复用同一个 key。
- 服务端内部幂等键格式为 `fu:{userId}:{Idempotent-Key}`，写入 `idempotent_record`。
- 新增 `file_upload_record` 保存上传响应元数据，用于重复请求返回同一 `fileUrl/fileName/fileSize/bizType`。
- 上传先保存到 `uploadDir/.tmp/{userId}` 并计算 SHA-256，再移动到 `bizType/userId/hashPrefix/sha256.ext`。
- 同 userId、同 key、同文件内容返回同一结果；同 key 不同文件内容返回 `409 / 2017`。
- 同 userId、同 `bizType`、同 SHA-256、同扩展名复用已有文件，避免重试或重复选择生成多个副本。
- 并发重复请求如首个请求仍在处理中，返回 `409 / 2018`，调用方可稍后用同一 key 重试。
