# User Service 接口业务逻辑说明

本文档基于 `nursing-user-service` 当前代码整理，覆盖用户、短信和文件上传相关接口的业务流程、鉴权方式、数据影响和主要异常分支。

## 一、公共说明

### 1. 统一返回

所有接口使用 `Result<T>` 作为响应体。业务异常由 `UserExceptionHandler` 捕获，并按 `UserBusinessException` 中的 HTTP 状态码和业务错误码返回。

### 2. 鉴权规则

以下接口需要请求头携带 `Authorization: Bearer <token>`：

| 接口 | 鉴权来源 |
|---|---|
| `POST /api/v1/users/logout` | `UserTokenInterceptor` 校验 Token |
| `GET /api/v1/users/profile` | `UserTokenInterceptor` 校验 Token 并写入 `request.userId` |
| `PATCH /api/v1/users/profile` | `UserTokenInterceptor` 校验 Token 并写入 `request.userId` |
| `POST /api/v1/files/upload` | `UserTokenInterceptor` 校验 Token |

Token 校验逻辑：

1. 从 `Authorization` 请求头解析 `Bearer ` 前缀。
2. 使用 JWT 密钥验签并校验过期时间。
3. 检查 Redis 黑名单 `jwt:blacklist:{tokenId}`。
4. 从 JWT claims 读取 `userId`，写入请求属性。

### 3. 关键配置

| 配置项 | 默认值 | 说明 |
|---|---:|---|
| `nursing.jwt.expire-seconds` | `604800` | JWT 有效期，默认 7 天 |
| `nursing.sms.rate-limit-seconds` | `60` | 同一手机号短信发送间隔 |
| `nursing.sms.phone-daily-limit` | `10` | 同一手机号每日短信次数上限 |
| `nursing.sms.ip-hourly-limit` | `60` | 同一 IP 每小时短信次数上限 |
| `nursing.sms.ip-daily-limit` | `300` | 同一 IP 每日短信次数上限 |
| `nursing.sms.verify-max-attempts` | `5` | 同一验证码最大错误次数 |
| `nursing.sms.expire-seconds` | `300` | 验证码有效期 |
| `nursing.sms.sign-name` | 环境变量 | 阿里云短信签名 |
| `nursing.file.upload-dir` | `uploads` | 文件落盘目录 |
| `nursing.file.public-base-url` | `http://gateway:8080/uploads` | 文件访问基础 URL |

## 二、接口明细

### 1. 发送短信验证码

| 项目 | 内容 |
|---|---|
| 路径 | `POST /api/v1/users/sms-code` |
| Controller | `SmsController.sendSmsCode` |
| Service | `SmsService.sendSmsCode` |
| 是否鉴权 | 否 |

请求体：

| 字段 | 规则 | 说明 |
|---|---|---|
| `phone` | 必填，`^1\d{10}$` | 手机号 |
| `smsType` | 必填，`register/login/reset_password` | 短信业务类型 |

业务流程：

1. 根据 `smsType` 校验手机号状态。
2. `register` 类型要求手机号未注册。
3. `login` 和 `reset_password` 类型要求手机号已注册。
4. 解析客户端 IP，优先 `X-Forwarded-For`，其次 `X-Real-IP`，最后使用远端地址。
5. 通过 Redis Lua 原子执行 60 秒频率限制、手机号每日上限、IP 小时上限和 IP 每日上限。
6. 生成 6 位数字验证码。
7. 将短信记录写入 `sms_record`，状态为 `PENDING`，验证码以 BCrypt 哈希保存。
8. 同步调用阿里云短信。
9. 阿里云接受成功后，将明文验证码写入 Redis：`sms:code:{smsType}:{phone}`，TTL 为 300 秒，并更新 `sms_record.status=SENT`。
10. 阿里云明确失败时，更新 `sms_record.status=FAILED`，释放短期限流键并返回短信发送失败。
11. 阿里云调用超时或结果未知时，更新 `sms_record.status=UNKNOWN`，不释放短期限流键，让 60 秒限制自然过期。
11. 返回验证码有效期。

主要数据影响：

| 数据位置 | 操作 |
|---|---|
| Redis | 原子写入发送限流和额度计数；阿里云成功后写入验证码缓存 |
| `sms_record` | 新增发送审计记录，并按结果更新状态 |

主要失败情况：

| 场景 | 结果 |
|---|---|
| 注册短信但手机号已注册 | 返回手机号已注册错误 |
| 登录/重置密码短信但手机号未注册 | 返回手机号未注册错误 |
| 60 秒内重复发送 | 返回发送过于频繁，并在 `data.retryAfterSeconds` 返回剩余等待秒数 |
| 手机号或 IP 超过发送上限 | 返回发送过于频繁或短信次数达到上限 |
| 阿里云短信发送失败 | 返回短信发送失败 |

### 2. 用户注册

| 项目 | 内容 |
|---|---|
| 路径 | `POST /api/v1/users/register` |
| Controller | `UserController.register` |
| Service | `UserService.register` |
| 是否鉴权 | 否 |
| 成功状态码 | `201 Created` |

请求体：

| 字段 | 规则 | 说明 |
|---|---|---|
| `phone` | 必填，`^1\d{10}$` | 手机号 |
| `smsCode` | 必填，6 位数字 | 注册验证码 |
| `password` | 必填，8-32 位，至少包含字母和数字 | 登录密码 |
| `nickname` | 可选，2-16 个字符 | 昵称 |

业务流程：

1. 根据手机号查询 `user` 表，若已存在则拒绝注册。
2. 校验 `register` 类型短信验证码。
3. 初始化用户对象。
4. 使用雪花算法生成用户 ID。
5. 使用 BCrypt 加密密码。
6. 未传昵称时，使用 `用户 + 手机号后四位` 作为默认昵称。
7. 初始化 `gender=0`、`status=0`、`isDeleted=0`、创建时间和更新时间。
8. 写入 `user` 表。
9. 生成 JWT，并写入 `user_token` 表和 Redis Token 记录。
10. 返回 Token、过期时间和脱敏后的用户信息。

主要数据影响：

| 数据位置 | 操作 |
|---|---|
| Redis | 删除已使用的短信验证码，写入 Token 记录 |
| `user` | 新增用户 |
| `user_token` | 新增 Token 记录 |

主要失败情况：

| 场景 | 结果 |
|---|---|
| 手机号已存在 | 返回注册手机号冲突 |
| 验证码不存在或过期 | 返回验证码已过期 |
| 验证码错误 | 返回验证码错误 |

### 3. 用户登录

| 项目 | 内容 |
|---|---|
| 路径 | `POST /api/v1/users/login` |
| Controller | `UserController.login` |
| Service | `UserService.login` |
| 是否鉴权 | 否 |

请求体：

| 字段 | 规则 | 说明 |
|---|---|---|
| `phone` | 必填，`^1\d{10}$` | 手机号 |
| `loginMode` | 必填，`password/sms` | 登录方式 |
| `password` | 密码登录时必填 | 登录密码 |
| `smsCode` | 短信登录时使用，6 位数字 | 登录验证码 |

业务流程：

1. 根据手机号查询用户。
2. 校验账号存在且未禁用。
3. 如果 `loginMode=password`，校验密码非空并使用 BCrypt 匹配。
4. 如果 `loginMode=sms`，校验验证码非空并验证 `login` 类型短信验证码。
5. 更新 `last_login_time`。
6. 生成 JWT，并写入 `user_token` 表和 Redis Token 记录。
7. 返回 Token、过期时间和脱敏后的用户信息。

主要数据影响：

| 数据位置 | 操作 |
|---|---|
| Redis | 短信登录时删除已使用验证码，写入 Token 记录 |
| `user` | 更新最后登录时间 |
| `user_token` | 新增 Token 记录 |

主要失败情况：

| 场景 | 结果 |
|---|---|
| 手机号未注册 | 返回手机号未注册 |
| 账号被禁用 | 返回账号已禁用 |
| 密码为空或错误 | 返回参数错误或密码错误 |
| 短信验证码为空、过期或错误 | 返回对应验证码错误 |

### 4. 用户登出

| 项目 | 内容 |
|---|---|
| 路径 | `POST /api/v1/users/logout` |
| Controller | `UserController.logout` |
| Service | `UserService.logout` |
| 是否鉴权 | 是 |

业务流程：

1. 拦截器先完成一次 Token 校验。
2. Controller 将 `Authorization` 请求头传入 Service。
3. Service 再解析并校验 Token。
4. 解析 JWT 中的 `tokenId`。
5. 按剩余有效期写入 Redis 黑名单：`jwt:blacklist:{tokenId}`。
6. 返回登出成功。

主要数据影响：

| 数据位置 | 操作 |
|---|---|
| Redis | 写入 Token 黑名单 |

主要失败情况：

| 场景 | 结果 |
|---|---|
| 请求头缺失或格式错误 | 返回未授权 |
| Token 过期、验签失败或已在黑名单 | 返回未授权或 Token 已拉黑 |

### 5. 重置密码

| 项目 | 内容 |
|---|---|
| 路径 | `POST /api/v1/users/password/reset` |
| Controller | `UserController.resetPassword` |
| Service | `UserService.resetPassword` |
| 是否鉴权 | 否 |

请求体：

| 字段 | 规则 | 说明 |
|---|---|---|
| `phone` | 必填，`^1\d{10}$` | 手机号 |
| `smsCode` | 必填，6 位数字 | 重置密码验证码 |
| `newPassword` | 必填，8-32 位，至少包含字母和数字 | 新密码 |

业务流程：

1. 根据手机号查询用户。
2. 校验 `reset_password` 类型短信验证码。
3. 使用 BCrypt 判断新密码是否与旧密码一致。
4. 将新密码 BCrypt 加密后更新到 `user` 表。
5. 返回密码重置成功。

主要数据影响：

| 数据位置 | 操作 |
|---|---|
| Redis | 删除已使用的重置密码验证码 |
| `user` | 更新密码和更新时间 |

主要失败情况：

| 场景 | 结果 |
|---|---|
| 手机号未注册 | 返回手机号未注册 |
| 验证码过期或错误 | 返回验证码错误 |
| 新密码与旧密码一致 | 返回新旧密码不能相同 |

### 6. 查询个人资料

| 项目 | 内容 |
|---|---|
| 路径 | `GET /api/v1/users/profile` |
| Controller | `UserController.getProfile` |
| Service | `UserService.getProfile` |
| 是否鉴权 | 是 |

业务流程：

1. 拦截器校验 Token，并将 `userId` 写入请求属性。
2. Service 根据 `userId` 查询 `user` 表。
3. 校验用户存在且账号未禁用。
4. 手机号脱敏。
5. 身份证号如已加密，则先解密再脱敏。
6. 返回用户资料、最后登录时间和创建时间。

主要数据影响：

| 数据位置 | 操作 |
|---|---|
| `user` | 查询用户资料 |

主要失败情况：

| 场景 | 结果 |
|---|---|
| Token 无效 | 返回未授权 |
| 用户不存在或已删除 | 返回未授权 |
| 账号被禁用 | 返回账号已禁用 |

### 7. 修改个人资料

| 项目 | 内容 |
|---|---|
| 路径 | `PATCH /api/v1/users/profile` |
| Controller | `UserController.updateProfile` |
| Service | `UserService.updateProfile` |
| 是否鉴权 | 是 |

请求体：

| 字段 | 规则 | 说明 |
|---|---|---|
| `nickname` | 可选，2-16 个字符 | 昵称 |
| `avatar` | 可选，最大 256 个字符 | 头像 URL |
| `gender` | 可选，0-2 | 性别 |
| `idCard` | 可选，18 个字符 | 身份证号 |

业务流程：

1. 拦截器校验 Token，并将 `userId` 写入请求属性。
2. Service 查询用户并校验账号状态。
3. 如传入身份证号，校验身份证格式和校验位。
4. 对身份证号使用 AES-GCM 加密后更新数据库。
5. 按非空字段动态更新用户资料。
6. 重新查询最新用户信息。
7. 返回用户 ID、昵称、头像和性别。

主要数据影响：

| 数据位置 | 操作 |
|---|---|
| `user` | 更新昵称、头像、性别、身份证号和更新时间 |

主要失败情况：

| 场景 | 结果 |
|---|---|
| Token 无效 | 返回未授权 |
| 用户不存在或账号禁用 | 返回未授权或账号已禁用 |
| 身份证号格式或校验位错误 | 返回身份证号格式不正确 |

### 8. 上传文件

| 项目 | 内容 |
|---|---|
| 路径 | `POST /api/v1/files/upload` |
| Controller | `FileController.upload` |
| Service | `FileStorageService.upload` |
| 是否鉴权 | 是 |
| 请求类型 | `multipart/form-data` |

请求参数：

| 字段 | 规则 | 说明 |
|---|---|---|
| `file` | 必填，非空，最大 10MB | 上传文件 |
| `bizType` | 必填，`avatar/review_image/complaint_image` | 业务类型 |

支持文件类型：

| 扩展名 | Content-Type |
|---|---|
| `jpg` | `image/jpeg` |
| `jpeg` | `image/jpeg` |
| `png` | `image/png` |
| `gif` | `image/gif` |
| `mp4` | `video/mp4` |

业务流程：

1. 拦截器校验 Token。
2. 校验 `bizType` 是否在允许列表中。
3. 校验文件非空且大小不超过 10MB。
4. 根据原始文件名提取扩展名。
5. 校验扩展名和 `Content-Type` 是否匹配。
6. 使用 UUID 生成新文件名。
7. 按当前日期生成目录：`yyyy/MM/dd`。
8. 规范化上传根目录、目标目录和目标文件路径，防止路径逃逸。
9. 创建目标目录并保存文件。
10. 返回文件名、大小、业务类型和公开访问 URL。

主要数据影响：

| 数据位置 | 操作 |
|---|---|
| 本地文件系统 | 将文件保存到 `uploadDir/yyyy/MM/dd/{uuid}.{ext}` |

主要失败情况：

| 场景 | 结果 |
|---|---|
| Token 无效 | 返回未授权 |
| `bizType` 不合法 | 返回参数错误 |
| 文件为空或保存失败 | 返回文件上传失败 |
| 文件超过 10MB | 返回文件过大 |
| 扩展名或 Content-Type 不支持 | 返回文件格式不支持 |

## 三、核心数据表关系

| 表 | 主要用途 |
|---|---|
| `user` | 保存用户账号、密码、昵称、头像、性别、身份证、状态和登录时间 |
| `sms_record` | 保存短信发送记录，验证码以 BCrypt 哈希落库 |
| `user_token` | 保存已签发 Token 的审计记录 |

## 四、Redis Key 说明

| Key | 来源 | 用途 |
|---|---|---|
| `sms:rate:{smsType}:{phone}` | `SmsRateLimiter` | 同业务类型短信发送频率限制 |
| `sms:quota:phone:day:{phone}:{yyyyMMdd}` | `SmsRateLimiter` | 手机号每日发送额度 |
| `sms:quota:ip:hour:{ip}:{yyyyMMddHH}` | `SmsRateLimiter` | IP 每小时发送额度 |
| `sms:quota:ip:day:{ip}:{yyyyMMdd}` | `SmsRateLimiter` | IP 每日发送额度 |
| `sms:code:{smsType}:{phone}` | `SmsService` | 短信验证码缓存 |
| `user:token:{userId}:{tokenId}` | `TokenService` | 已签发 Token 的 Redis 记录 |
| `jwt:blacklist:{tokenId}` | `TokenService` | 登出后的 Token 黑名单 |
