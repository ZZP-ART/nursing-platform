# 后端闭环修复说明

日期：2026-07-16

## 本次范围

本次只补后端能力，不包含前端工程。

## 已补齐能力

- 编译断点：反馈服务不再引用已移除的 `OrderStatus.WAITING_SERVICE`，投诉状态校验改为支持新订单状态机中的待派单、已派单、已接单、服务中、待用户确认和已完成。
- 网关鉴权：修复 Redis 授权版本测试夹具和 `Mono<Void>` 成功路径被 `switchIfEmpty` 误判的问题；护理员申请入口允许已登录用户提交或查询，护理员业务接口仍要求 `CAREGIVER`。
- 护理员审核：`nursing-operations-service` 支持申请、查询本人申请、管理员待审列表、通过、拒绝；被拒绝后可重新提交。
- 目录上线：`nursing-catalog-service` 支持管理员创建/编辑分类、服务项目和规格，并通过 publish/unpublish 手动上线或下架；公开查询仍只展示已上架数据。
- 评价审核：`nursing-feedback-service` 支持管理员分页查看评价，并将评价审核为通过或驳回。
- 投诉处理：`nursing-feedback-service` 支持管理员分页查看投诉，更新投诉为处理中、已解决或已关闭，并追加投诉轨迹，用户可继续通过投诉轨迹接口查询进度。
- Compose 配置：`docker-compose/.env` 已补充 operations 服务数据库 URL、用户名和密码，Compose 配置可正常展开。

## 新增主要接口

### 护理员申请

- `POST /api/v1/caregiver/applications`
- `GET /api/v1/caregiver/applications/me`
- `GET /api/v1/admin/caregiver-applications`
- `POST /api/v1/admin/caregiver-applications/{userId}/approve`
- `POST /api/v1/admin/caregiver-applications/{userId}/reject`

### 目录管理

- `POST /api/v1/admin/catalog/categories`
- `PUT /api/v1/admin/catalog/categories/{id}`
- `POST /api/v1/admin/catalog/categories/{id}/publish`
- `POST /api/v1/admin/catalog/categories/{id}/unpublish`
- `POST /api/v1/admin/catalog/items`
- `PUT /api/v1/admin/catalog/items/{id}`
- `POST /api/v1/admin/catalog/items/{id}/publish`
- `POST /api/v1/admin/catalog/items/{id}/unpublish`
- `POST /api/v1/admin/catalog/specs`
- `PUT /api/v1/admin/catalog/specs/{id}`
- `POST /api/v1/admin/catalog/specs/{id}/publish`
- `POST /api/v1/admin/catalog/specs/{id}/unpublish`

### 反馈管理

- `GET /api/v1/admin/feedback/reviews`
- `POST /api/v1/admin/feedback/reviews/{id}/moderate`
- `GET /api/v1/admin/feedback/complaints`
- `POST /api/v1/admin/feedback/complaints/{id}/handle`
